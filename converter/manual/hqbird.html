What is in HQbird 2027

One setup installs the Firebird server and the tools that look after it. The parts work together, and you can use only the parts that you need.

HQbird server

Firebird 2.5, 3.0, 4.0 and 5.0 built by IBSurgeon, with engine features that regular Firebird does not have: NGRAM index, materialized views, index creation under load, faster BLOBs, query substitution and more.

Agent and HQ Monitor

The agent (fbagent) makes and checks backups, runs maintenance and collects metrics. HQ Monitor is the web console: dashboard, server health report, performance report, errors, locks, jobs and backups.

HQCenter

Your own management center for many servers: states, versions, licenses, settings and updates in one console. Database servers need no open incoming ports; all traffic uses mTLS.

HQbird Cluster

Replication master to replica for Firebird 2.5 to 5.0, set up from a web page (RCM). Replica initialization without a stop of the master, lag control, data check, step-by-step switchover.

HQbird MCP

An MCP server for AI assistants (Claude, Cursor, Codex and others) with more than 120 tools for Firebird. Reads use read-only transactions; a person confirms every change, and dangerous operations only on the server.

Updates with rollback

The agent, HQ Monitor, the cluster programs, the MCP server and Firebird itself update automatically, with a signature check and an automatic rollback if the update fails.

What HQbird does for you

Enterprise with large databases

Typical problems that HQbird solves for large and highly loaded Firebird databases:

  1. Backups that you cannot trust. gbak and nbackup jobs on a schedule, a test restore of each backup, compression with a check of the archive, backup directly to S3 or FTP, and retention by levels. The backup inventory shows each database that has no recent backup.
  2. Slow performance and degradation over time. The HQbird server is faster than regular Firebird (BLOB cache in temporary space, multi-thread backup, restore and sweep in 2.5–4.0, NGRAM index in 5.0). Sweep, index statistics and the "backup, restore, replace" cycle run in a maintenance window, with checks and automatic rollback.
  3. No clear picture of the server. A daily server health report with risks and actions; monitoring each minute without a trace (LWM); transactions, locks and deadlocks with the SQL of both sides; which program loads the disk and the CPU; Linux limits that stop Firebird under load.
  4. Slow queries in the application. The performance report groups the trace by plan and shows the slowest and the most frequent queries, SQL errors with the application name and IP address, and the client versions.
  5. Problems found too late. Alerts by email, Telegram and webhooks (Slack, Teams, Discord and others), metrics export to Prometheus and Grafana.

SaaS and many servers

One server with hundreds of databases (a database for each client), or hundreds of servers at your customers:

  • Group jobs. One job backs up or maintains all databases in a folder, by a mask. Backups, test restores and sweeps of hundreds of databases are set up once.
  • HQCenter. All servers on one page with their states, Firebird and agent versions and licenses. Settings go to the servers with delivery states and rollback; updates go out from the center. The database servers only connect out.
  • Users and permissions for each server, with an audit log, and a weekly report for all servers. The console has 5 languages: English, Russian, German, Portuguese (Brazil), Spanish.
  • Lower cloud costs. If your SaaS in Amazon, Azure, Oracle Cloud or a similar cloud is slow or costs too much, HQbird shows which databases and queries make the load.

High availability: HQbird Cluster

  • Replication from master to replica for Firebird 2.5, 3.0, 4.0 and 5.0. One replica can receive databases from many masters.
  • Replica initialization with nbackup: the master does not stop. HQbird checks the free space and the long transactions first.
  • Replica lag and 20 alert types with instructions, a data check of the replica, and a step-by-step switchover (Promote). HQbird never restarts the Firebird of the master automatically.
  • Replication of HQbird 2024 is taken over by the cluster manager when you upgrade.

Developers and AI assistants: HQbird MCP

  • Query plans and index advice, a compile check of a query, comparison of schemas and data of two databases, migrations with a plan and a rollback plan, directly from Cursor, Claude Code or another MCP client.
  • The assistant sees the data of the agent: health report, monitoring, gstat, performance and deadlock reports, backup states.
  • A person always decides. Dangerous operations need an open maintenance window and a fresh checked backup, and they are confirmed only on the server. Each decision is in an audit log with a hash chain.

Frequently asked questions

How is Firebird related to HQbird?

HQbird is an enterprise version of the open source Firebird DBMS. In open source projects, the free version is called "vanilla": there is a vanilla PostgreSQL and commercial versions such as EnterpriseDB and Postgres Pro. HQbird is not a different database: you do not need a backup and restore to switch between HQbird and Firebird, and you do not need to change SQL or client applications.

Is Firebird compatible with HQbird?

Yes. You can install HQbird and vanilla Firebird side by side on one server, work with a database in HQbird, then switch to vanilla Firebird, and back. 100% compatibility with vanilla Firebird is the most important feature of HQbird.

When do HQbird features appear in vanilla Firebird?

Almost all features made for HQbird come to Firebird within 1–2 versions. Replication was in HQbird for 2.5 and came to vanilla Firebird 4.0. External connection pooling was made in HQbird 3.0 and came to Firebird 4.0. Multi-thread backup, restore and sweep were in HQbird from 2.5 and came to vanilla Firebird 5.0.

I have HQbird 2024. How do I move to HQbird 2027?

Run the HQbird 2027 setup (Windows) or installer (Linux) on the server. It finds the older HQbird, updates Firebird in place, imports the FBDataGuard jobs into the new agent, and the cluster manager takes over the replication. Make a backup of every database before you start.

Does HQbird need Internet access?

No. The setups are offline, HQ Monitor works in closed networks, and a license file can be installed without a connection. Internet access is used only for the trial request, automatic updates and alerts to external services such as Telegram.

How does a purchase in the FirebirdSQL shop help Firebird?

When you buy HQbird through the FirebirdSQL shop, the Firebird Foundation receives a commission. It directly funds the development of free open source Firebird, its drivers and the related infrastructure.
